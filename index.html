PHP2Shell checker

Is your site affected by PHP2Shell?

PHP2Shell is the name used for two PHP vulnerabilities disclosed on 21 October 2026: CVE-2026-109618 and CVE-2026-109619. They can allow unauthenticated remote code execution on PHP installations that serve web requests. The PHP project published fixed releases the same day.

The practical step is to run a fixed release. Header checks on this page are only a first look at the version a server chooses to advertise.

Fixed versions

Upstream PHP releases that include the 21 October 2026 fixes
Branch Fixed release
PHP 8.5 8.5.12
PHP 8.4 8.4.27
PHP 8.3 8.3.36
PHP 8.2 8.2.35

PHP 8.1 and older are out of upstream support. They do not get a fixed point release for this issue, so those installs need an upgrade to a supported branch: 8.2.35, 8.3.36, 8.4.27, 8.5.12, or a later release on those branches.

Disclaimer

A header version check can overstate exposure. Linux distributions and long-term support vendors often backport fixes without changing the version string PHP reports. This is not a confirmed exploit test.

“Likely affected” means the advertised version is older than the upstream fix. It does not mean the site has been compromised, and it does not mean an attack would succeed. “Likely patched”, “end of life”, and “not PHP” are not guarantees. Confirm the PHP build that actually serves the site, or ask the host.

Free header check

Enter a public website address. The checker requests that URL with a normal GET and reads response headers only: X-Powered-By, Server, and a few WordPress hints (Link, X-Pingback, X-Redirect-By). It sends no request body, no file upload, and nothing intended to trigger the bug. HTTPS is used when you leave the scheme off, and it is tried first if you enter HTTP.

Nothing you submit is sent to an analytics service. The address is used only for this header request.

What the labels mean

Likely affected
Headers advertise a supported branch older than the fixed release. Read the disclaimer before treating that as the final word.
Likely patched
Headers advertise 8.2.35, 8.3.36, 8.4.27, 8.5.12, or a later point release on those branches.
End of life
Headers advertise PHP 8.1 or older. The PHP project does not ship this fix on those branches.
Not PHP
Headers name another stack and do not mention PHP.
Unknown
Headers do not include a PHP version. WordPress sites often fall here because the version is hidden.
